## How to work in this project

- `requirements.md` is the source of truth. If code and the file disagree, say so and ask; don't change either silently.
- Don't invent content. An empty section stays empty with "to fill in" until the team answers. This applies to column names and units in section 3 above all.
- Ask one question at a time and wait for the answer. Before asking, check the data files and the existing code, and say what you derived from them.
- Every answer lands in `requirements.md`: a decision goes to section 6 as D-xx, an open question goes to section 5 as Q-xx with an owner. Propose the edit and wait for approval before writing it.
- You propose options with a one-line reason; the team decides.
- Build in the order of the milestones in section 14. After each milestone, run `/dod` and give the command to start the app, then wait for confirmation before continuing.
- When changing existing code, show the file and one or two lines before and after the change.
- Ask before adding a library, deleting or renaming a file, or committing.
- If a milestone is late, cut nice-to-haves from section 4, not testing.
